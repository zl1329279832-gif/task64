# 角色与前台能力对照

> 本文档梳理三种角色（管理员、教师、学生）在各模块的可见范围与操作权限，
> 并标注前端页面与后端接口之间的已知不一致。

---

## 1 角色定义

| 角色 | 存储表 | 登录接口 | Token 中 role 值 |
|---|---|---|---|
| 管理员 | `users` | `/users/login` | `"管理员"` |
| 教师 | `jiaoshi` | `/jiaoshi/login` | `"教师"` |
| 学生 | `xuesheng` | `/xuesheng/login` | `"学生"` |

认证机制：所有非 `@IgnoreAuth` 标注的接口均需在 HTTP Header 中传递 `Token` 字段。
拦截器 `AuthorizationInterceptor` 校验 token 表记录是否有效且未过期（默认 1 小时）。

## 4 已知文档-前端不一致

### 4.1 recharge.html 无后端接口

**位置**：`src/main/resources/front/front/pages/recharge/recharge.html`

**现状**：

该页面是一个充值/支付界面，包含：
- 充值金额输入框（`newMoney`）
- 支付方式单选按钮：微信支付、支付宝、中国建设银行、农业银行、中国银行、交通银行
- 提交按钮

**实际行为**：

点击提交后，页面执行以下 JavaScript 逻辑：
```javascript
// 1. 从 localStorage 读取当前用户信息
var user = JSON.parse(localStorage.getItem('userTable'));
// 2. 在本地累加金额
user.newMoney = parseFloat(user.newMoney) + parseFloat(newMoney);
// 3. 调用用户表的 update 接口写回
fetch('${table}/update', { method: 'POST', body: JSON.stringify(user) });
```

**问题**：

| 维度 | 说明 |
|---|---|
| **无支付网关对接** | 页面展示了微信/支付宝/银行支付选项，但后端无任何支付回调、订单创建或交易记录接口 |
| **金额在客户端计算** | `newMoney` 累加在前端 JavaScript 中完成，未做服务端校验，用户可篡改 |
| **直接调用用户表 update** | 充值操作本质上是修改用户记录的 `new_money` 字段，无任何财务审计日志 |
| **无接口鉴权区分** | `${table}/update` 是通用的用户信息更新接口，并非充值专用接口 |

**结论**：`recharge.html` 是一个**纯 UI 占位页面**，不具备真实支付能力。
若系统需要充值功能，需对接第三方支付 SDK 并新建专用的充值/订单后端接口。
当前该页面**建议对生产环境隐藏入口或添加"功能开发中"提示**。

### 4.2 其他前端-后端差异

| 差异点 | 说明 |
|---|---|
| Apache Shiro 依赖未使用 | `pom.xml` 引入了 Shiro 1.3.2，但实际认证由 `AuthorizationInterceptor` 处理，Shiro 未配置 |
| 科研成果点击数竞态 | `keyanchengguo` 的 clicknum 采用读-改-写方式递增，与名片的原子递增方式不一致，高并发下可能丢数 |
| 排序字段注入 | 所有 Mapper XML 使用 `${params.orderBy}` 拼接排序字段（字符串插值而非参数绑定），存在 SQL 注入风险 |
| 密码明文存储 | 所有用户密码明文存储，重置密码默认值为 "123456" |

## 5 权限控制实现说明

本系统**未使用 RBAC 权限表**，所有权限判断硬编码在 Controller 方法内部，模式如下：

```java
// 典型角色判断模式（伪代码）
String role = (String) request.getSession().getAttribute("role");
if ("教师".equals(role)) {
    // 自动注入 jiaoshiId = userId，限制查询范围
    params.put("jiaoshiId", request.getSession().getAttribute("userId"));
} else if ("学生".equals(role)) {
    // 自动注入 xueshengId = userId
    params.put("xueshengId", request.getSession().getAttribute("userId"));
}
// 管理员不加限制，可查看全部
```

### 运维影响

- **新增角色**：需要修改所有相关 Controller 的 if/else 分支，无法通过数据库配置。
- **权限变更**：同上，需修改 Java 代码并重新部署。
- **审计困难**：无操作日志表，无法追溯谁在何时执行了审核/回退/删除等操作。
